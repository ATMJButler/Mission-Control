# Mission Control Apps Script deployment

The canonical Apps Script source is `google_apps_script_Code.gs`.

Production deployment is handled by the GitHub Actions workflow **Deploy Apps Script**. Normal qualifying GitHub pushes may trigger it automatically, but connector-authored commits have been observed not to start the push workflow. For backend changes made through ChatGPT/GitHub connector, explicitly run **Deploy Apps Script** with `workflow_dispatch` until an automated dispatcher is commissioned.

Required GitHub Actions secrets:

- `CLASPRC_JSON` — clasp OAuth credential JSON generated by `clasp login`. Treat as a high-value secret.
- `.clasp.json` is checked into the repository and contains the non-secret Apps Script `scriptId`; no `CLASP_JSON` secret is required.
- `APPS_SCRIPT_DEPLOYMENT_ID` — the existing production web-app deployment ID.

The Apps Script API must be enabled for the Google account used by clasp.

Release flow:

1. Update/test `google_apps_script_Code.gs`.
2. Commit to GitHub.
3. For connector-authored backend commits, manually dispatch **Deploy Apps Script** from `main`. For ordinary GitHub pushes, verify that the qualifying push actually started the workflow rather than assuming it did.
4. Workflow pushes the source, creates an immutable Apps Script version, and updates the existing production deployment.
5. Verify Mission Control behavior/readback after deployment.

Never commit `.clasprc.json`, OAuth refresh tokens, or private Mission Control sync tokens.


Runtime secrets:

- Vercel `MC_SYNC_TOKEN` and Apps Script Script Property `SYNC_TOKEN` must contain the same dedicated random value.
- Apps Script authorization reads `SYNC_TOKEN` from `PropertiesService`; no sync token belongs in source code.
- Vercel `MC_SYNC_URL` must be the production Apps Script **Web app** `/exec` URL, not a Library URL.
- `APPS_SCRIPT_DEPLOYMENT_ID` must identify that same Web app deployment.
